## 🏗️ ARQUITECTURA GENERAL

### Patrón Arquitectónico: Microservicios con Orquestador Central

```
┌─────────────────────────────────────────────────────────────┐
│                   WHATSAPP BUSINESS API                    │
│                     (Punto de Entrada)                     │
└─────────────────────┬───────────────────────────────────────┘
                      │ Webhook HTTP POST
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                  SERVIDOR RAILWAY                          │
│  ┌─────────────────────────────────────────────────────┐   │
│  │            ORQUESTADOR CENTRAL                      │   │
│  │  - Recepción de webhooks                           │   │
│  │  - Selección de agente apropiado                   │   │
│  │  - Gestión de transferencias                       │   │
│  │  - Coordinación de estado                          │   │
│  └─────────────────────────────────────────────────────┘   │
│                           │                               │
│     ┌─────────────────────┼─────────────────────┐         │
│     ▼                     ▼                     ▼         │
│  ┌─────────┐         ┌─────────┐         ┌─────────┐      │
│  │ AGENTE  │         │ AGENTE  │         │ AGENTE  │      │
│  │   DE    │         │   DE    │         │   DE    │      │
│  │RECEPCIÓN│         │ SOPORTE │         │LEADSALES│      │
│  └─────────┘         └─────────┘         └─────────┘      │
└─────────────────────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                 SERVICIOS EXTERNOS                         │
│  • Gemini API (LLM)    • Leadsales API (CRM)              │
│  • RAG Vector DB       • WhatsApp Graph API               │
└─────────────────────────────────────────────────────────────┘
```

### Principios de Diseño

1. **Separación de Responsabilidades**: Cada agente tiene una función específica
2. **Orquestación Centralizada**: Un solo punto de control para decisiones
3. **Estado Compartido**: Base de datos común para contexto conversacional
4. **Servicios Externos**: APIs especializadas para cada dominio
5. **Escalabilidad Horizontal**: Fácil adición de nuevos agentes

## 🧩 COMPONENTES DEL SISTEMA

### 1. Orquestador Central (`app/core/orchestrator.py`)

**Responsabilidades:**
- Recibir y validar webhooks de WhatsApp
- Determinar qué agente debe procesar cada mensaje
- Gestionar transferencias entre agentes
- Mantener el estado de conversaciones
- Aplicar el Handoff Protocol

### 2. Agente de Recepción (`app/agents/reception_agent.py`)

**Estados que maneja:**
- `NUEVO`: Primera interacción
- `RECOPILANDO_NOMBRE`: Solicitud y validación de nombre
- `RECOPILANDO_NECESIDAD`: Clasificación de intención

### 3. Agente de Soporte (`app/agents/support_agent.py`)

**Capacidades:**
- Búsqueda semántica en base de conocimiento
- Generación de respuestas contextuales
- Follow-up inteligente para más preguntas

### 4. Agente de Leadsales (`app/agents/leadsales_agent.py`)

**Funciones:**
- Compilación de datos del cliente
- Creación automática de lead en CRM
- Activación del Handoff Protocol
- Manejo de errores de integración

## 🔗 ESPECIFICACIONES DE APIS

### WhatsApp Business API

**Webhook Endpoint:** `POST /webhook`
```json
{
  "entry": [{
    "changes": [{
      "value": {
        "messages": [{
          "from": "573123456789",
          "type": "text",
          "text": {"body": "Hola, necesito información"}
        }]
      }
    }]
  }]
}
```

### Gemini API

**Clasificación de Intención:**
```python
POST https://generativelanguage.googleapis.com/v1/models/gemini-pro:generateContent
```

### Leadsales API

**Creación de Lead:**
```python
POST {LEADSALES_API_URL}/leads
```

## 💾 BASE DE DATOS Y ESTADO

### SQLite Schema

```sql
CREATE TABLE conversations (
    whatsapp_id TEXT PRIMARY KEY,
    state TEXT NOT NULL,
    customer_name TEXT,
    customer_needs TEXT,
    lead_id TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
